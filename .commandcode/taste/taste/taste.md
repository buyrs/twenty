# Taste
- Prefers running / developing applications locally on their Mac (macOS) rather than in cloud or hosted environments. Confidence: 0.7
- Prefers a low-friction, one-click launch experience for apps (e.g. a double-clickable .app / desktop icon) over manual terminal or multi-step startup. Confidence: 0.7
- Prefers self-hosted / bring-your-own-key (BYOK) setups where they control their own infrastructure and API keys over depending on vendor-hosted services. Confidence: 0.6
- Prefers full, complete end-to-end installations/verification over partial or staged setup — when asked to proceed, wants the whole task finished (deps, config, DB, running the app, and verifying it works). Confidence: 0.6
- Prefers implementation plans to be written out as a named markdown file (e.g. nativeapp.md) rather than delivered only as chat discussion. Confidence: 0.6
- Prefers plan/design documents to live at the repo root level (visible in the repository) rather than in hidden tool directories (e.g. ~/.commandcode/plans). Confidence: 0.6
- Prefers staying within the repo's existing stack (Node/TypeScript, e.g. Electron) over introducing new toolchains (e.g. Rust/Tauri) when packaging apps. Confidence: 0.6
- Prefers self-contained app bundles that embed their own dependencies (Postgres/Redis binaries) over relying on externally-installed services (brew, Docker). Confidence: 0.7
